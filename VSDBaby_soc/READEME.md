# 1. VSDBabySoC Introduction

VSDBabySoC is a small System-on-Chip that integrates digital and analog functional blocks.

The main blocks of the VSDBabySoC are:

- **RVMYTH** – RISC-V based processor
- **AVSDPLL** – Phase Locked Loop
- **AVSDDAC** – Digital-to-Analog Converter

The main wrapper module connecting these blocks is:

```text
vsdbabysoc
```

The basic simulation flow studied in this experiment was:

```text
RTL Design
    ↓
Pre-Synthesis Simulation
    ↓
Synthesis
    ↓
Gate-Level Netlist
    ↓
Post-Synthesis Simulation
    ↓
Waveform Analysis
```

# 3. RVMYTH RISC-V Processor

RVMYTH is the RISC-V based processor core used in the VSDBabySoC.

It acts as the main digital processing block of the SoC.

The RVMYTH processor receives the clock generated by the AVSDPLL and processes the required digital operations.

The digital output generated by RVMYTH is provided to the AVSDDAC block.

The main RVMYTH-related files used in the simulation include:

```text
rvmyth.v
rvmyth_gen.v
rvmyth.tlv
```

The RVMYTH block can be represented as:

```text
             ┌───────────────────┐
             │      RVMYTH       │
             │                   │
Clock ──────►│   RISC-V Core     │
             │                   │
             │ Digital Processing│
             └─────────┬─────────┘
                       │
                       │ Digital Data
                       ▼
                    AVSDDAC
```

RVMYTH therefore forms the digital processing core of the VSDBabySoC.

---

# 4. AVSDPLL

AVSDPLL is the Phase Locked Loop block of the VSDBabySoC.

The PLL is responsible for generating the clock signal required by the digital processing block.

The generated clock is supplied to the RVMYTH processor.

The main PLL source file is:

```text
avsdpll.v
```

The basic operation can be represented as:

```text
Input Clock
     │
     ▼
┌───────────────┐
│    AVSDPLL    │
│      PLL      │
└───────┬───────┘
        │
     Clock
        │
        ▼
     RVMYTH
```

---

# 5. AVSDDAC

AVSDDAC is the Digital-to-Analog Converter block of the VSDBabySoC.

It receives digital data from the RVMYTH processor and produces the corresponding output.

The main DAC source file is:

```text
avsddac.v
```

The basic operation can be represented as:

```text
Digital Data
     │
     ▼
┌───────────────┐
│   AVSDDAC     │
│      DAC      │
└───────┬───────┘
        │
        ▼
       OUT
```

# 6. Pre-Synthesis Simulation

Pre-synthesis simulation is performed on the RTL design before synthesis.

The purpose of this simulation is to verify the functional behavior of the VSDBabySoC RTL design.

## 6.1 RTL Files

The main files used for the pre-synthesis simulation include:

```text
testbench.v
vsdbabysoc.v
rvmyth.v
rvmyth_gen.v
rvmyth.tlv
avsdpll.v
avsddac.v
clk_gate.v
```

Other required source and include files are used during compilation.

---

## 6.2 Compilation

The RTL design was compiled using Icarus Verilog.

Navigate to the module directory:

```bash
cd ~/baby_soc/BabySoC_Simulation/src/module
```

The pre-synthesis compilation command is:

```bash
iverilog -o ./pre_synth_sim.out \
-DPRE_SYNTH_SIM \
testbench.v \
-I ../include \
-I .
```

---

## 6.3 Running the Pre-Synthesis Simulation

The compiled simulation can be executed using:

```bash
vvp ./pre_synth_sim.out
```

The simulation generates the VCD waveform file:

```text
pre_synth_sim.vcd
```

---

## 6.4 Pre-Synthesis Waveform

The generated waveform can be viewed using GTKWave:

```bash
gtkwave pre_synth_sim.vcd
```

The waveform is used to observe the behavior of the VSDBabySoC during RTL simulation.

Important signals such as clock, reset and output signals can be analyzed using GTKWave.

---

# 7. Post-Synthesis Simulation

Post-synthesis simulation is performed after synthesis using the gate-level representation of the design.

The purpose of post-synthesis simulation is to verify that the synthesized design maintains the expected functionality of the RTL design.

This process is also known as **Gate-Level Simulation (GLS)**.

---

## 7.1 Gate-Level Netlist

During synthesis, the RTL description is converted into a gate-level netlist.

The synthesized design is mapped to technology-specific cells from the SKY130 standard cell library.

The gate-level netlist is then used for post-synthesis simulation.

---

## 7.2 Post-Synthesis Simulation

The gate-level design is simulated using Icarus Verilog.

The synthesized netlist and required library files are used during the simulation.

The post-synthesis simulation produces the corresponding VCD waveform.

```text
post_synth_sim.vcd
```

---

## 7.3 Post-Synthesis Waveform

The generated waveform can be viewed using GTKWave:

```bash
gtkwave post_synth_sim.vcd
```

The waveform is analyzed to observe the behavior of the synthesized design.

---

# 8. Pre-Synthesis vs Post-Synthesis

The pre-synthesis and post-synthesis simulations were compared to understand the behavior of the design before and after synthesis.

| Parameter | Pre-Synthesis | Post-Synthesis |
|---|---|---|
| Design representation | RTL | Gate-level netlist |
| Design stage | Before synthesis | After synthesis |
| Purpose | Functional verification | Gate-level verification |
| Simulation | RTL simulation | GLS |
| Technology mapping | Not performed | SKY130 standard cells |
| Waveform | `pre_synth_sim.vcd` | `post_synth_sim.vcd` |
| Waveform viewer | GTKWave | GTKWave |

The complete flow is:

```text
RTL Design
    ↓
Pre-Synthesis Simulation
    ↓
pre_synth_sim.vcd
    ↓
Synthesis
    ↓
Gate-Level Netlist
    ↓
Post-Synthesis Simulation
    ↓
post_synth_sim.vcd
    ↓
Waveform Comparison
```
